# T-001: タスクを追加する add コマンド

## 概要

`mdtask add <title>` を追加する。カレントディレクトリの `tasks.md` の末尾に、Markdown のチェックリスト1行 `- [ ] <title>` を追記する。ファイルがなければ新しく作る。成功したら、追加したタスクの番号（ファイルの中で何件目のタスクか）とタイトルを標準出力に `Added task <N>: <title>` と出す。タイトルが空のときは標準エラーにエラーを出し、終了コード 1 で終わる。このときファイルは変更しない。あわせてヘルプ（Usage）の Commands 欄に add を載せる。

## 振る舞い

- コマンドの形式は `mdtask add <title...>`。`add` のあとに続く引数をすべて半角スペース1つでつないだものをタイトルとする（例: `mdtask add Buy milk` のタイトルは `Buy milk`）。`add` より後ろの引数はオプションとして解釈せず、`-` で始まっていてもタイトルの一部として扱う
- タイトルの前後の空白（スペース、タブ）は取り除く。取り除いた結果が空文字列のとき（引数がない場合、空文字列 `""` の場合、空白だけの場合）はエラーとする。標準エラーに `mdtask: task title is required\n` を出し、標準出力には何も出さず、終了コード 1 で終わる。`tasks.md` は作らず、すでにあれば変更しない
- タイトルに改行文字（`\n` または `\r`）が含まれる場合はエラーとする。チェックリストの1行が複数行に割れるのを防ぐため。標準エラーに `mdtask: task title must be a single line\n` を出し、標準出力には何も出さず、終了コード 1 で終わる。`tasks.md` は作らず、すでにあれば変更しない
- 対象のファイルはカレントディレクトリの `tasks.md` に固定する。UTF-8 で読み書きする
- `tasks.md` がない場合は新しく作り、内容を `- [ ] <title>\n` とする
- `tasks.md` がある場合は、既存の内容を1バイトも変えずに、末尾に `- [ ] <title>\n` を追記する。既存の内容が空でなく、末尾が `\n` で終わっていない場合は、先に `\n` を1つ補ってから追記する。既存の内容が空（0 バイト）の場合は、そのまま `- [ ] <title>\n` を書く
- タスクの番号は、追記したあとの `tasks.md` で、行頭（インデントなし）が `- [ ] `、`- [x] `、`- [X] ` のどれかで始まる行を上から数えたときの、追加した行の順番（1 始まり）とする。完了済みのタスク（`[x]` / `[X]`）も数に入れる。見出しや本文などチェックリスト以外の行は数えない
- 成功したときは、標準出力に `Added task <N>: <title>\n` を出す（`<N>` は上で決めた番号、`<title>` は前後の空白を取り除いたタイトル）。標準エラーには何も出さず、終了コード 0 で終わる
- ヘルプ（`mdtask`、`mdtask -h`、`mdtask --help` の出力と、不明なコマンドのときに標準エラーに出す Usage）の Commands 欄を、`  (none yet)` の行から `  add <title>    Add a task to tasks.md` の行に置き換える。ヘルプの全文は次のとおり: `Usage: mdtask <command> [options]\n\nCommands:\n  add <title>    Add a task to tasks.md\n\nOptions:\n  -h, --help     Show this help\n  -v, --version  Show the version\n`

## 受け入れ条件

### AC1

- 前提: `tasks.md` がないディレクトリ
- 操作: `mdtask add Buy milk` を実行する
- 結果: 終了コードは 0、標準出力は `Added task 1: Buy milk\n`、標準エラーは空。`tasks.md` が作られ、内容がちょうど `- [ ] Buy milk\n` になる

### AC2

- 前提: 内容が `- [ ] Buy milk\n` の `tasks.md` があるディレクトリ
- 操作: `mdtask add "Write report"` を実行する
- 結果: 終了コードは 0、標準出力は `Added task 2: Write report\n`、標準エラーは空。`tasks.md` の内容がちょうど `- [ ] Buy milk\n- [ ] Write report\n` になる

### AC3

- 結果: 終了コードは 0、標準出力は `Added task 3: Next\n`（見出しと本文は数えず、完了済みのタスクは数える）。`tasks.md` の内容がちょうど `# Tasks\n\nSome notes.\n- [x] Done task\n- [ ] Open task\n- [ ] Next\n` になる

## 範囲外

- タスクの一覧表示・完了・削除・編集など、add 以外のコマンド
- `mdtask add --help` のようなサブコマンドごとのヘルプやオプション
- `tasks.md` 以外のファイルを指定するオプションや環境変数
- インデントされたチェックリスト（入れ子のタスク）や、`*` / `+` を使うリスト記法を番号の数に入れること
- 改行コードが CRLF のファイルの扱い（改行の正規化はしない。CRLF が混ざっていても既存の内容はそのまま残し、追記する行は `\n` で終える）
- タイトルの重複チェック、長さの上限、Markdown の特殊文字のエスケープ
- 同時に複数のプロセスが書き込むときの排他制御
- `tasks.md` が読めない・書けないとき（権限エラーなど）のメッセージを決めること（終了コードが 1 以上になることだけを求める）

## 決定事項（人の承認時に確定）

- 複数の引数は、半角スペース1つでつないで1つのタイトルにする（`mdtask add Buy milk` のタイトルは `Buy milk`）
- `add` より後ろの引数はオプションとして解釈しない（`mdtask add --help` は `--help` というタスクを追加する）
- タイトルの前後の空白は取り除く
- 改行を含むタイトルはエラーにする（`mdtask: task title must be a single line`）。チェックリストの1行が複数行に割れて、ファイルの書式が壊れるのを防ぐため
- 番号は、行頭が `- [ ] ` / `- [x] ` / `- [X] ` の行だけを数え、完了済みも数に入れる。今後の list コマンドや done コマンドでも同じ番号を使う
- 出力の文言は `Added task <N>: <title>`、エラーは `mdtask: task title is required` とする
- ヘルプの Commands 欄の説明は `add <title>    Add a task to tasks.md` とする

## 実装の方針（受け入れ条件ではない）

- product/CLAUDE.md の「`cli.ts` の `run()` は副作用を持たせない」という設計ルールは守る
- `run()` は、ファイルの読み書きを行う小さなインターフェース（例: `tasks.md` の内容を読む関数と書く関数）を引数で受け取る。実際のファイル操作の実装は `main.ts` から渡す
- 単体テストでは、メモリ上の偽の実装を渡して `run()` を確かめられるようにする
