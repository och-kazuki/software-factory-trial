# mdtask（題材プロダクト）

Markdown ファイルでタスクを管理する CLI です。ソフトウェアファクトリーの題材として、工場のエージェントが機能を実装していきます。

## 技術スタック

- TypeScript。Node.js 24 の型除去機能でそのまま実行するので、ビルドの工程はない
- 実行時の依存パッケージは使わない（Node.js の標準モジュールだけを使う）
- テストは `node:test` で書く

## コマンド

| 目的                                                     | コマンド                             |
| -------------------------------------------------------- | ------------------------------------ |
| 実行                                                     | `node product/src/main.ts <command>` |
| 全チェック（型チェック、lint、テスト、秘密情報スキャン） | `npm run check`                      |
| テストだけ                                               | `npm test`                           |
| 整形と、自動で直せる lint の修正                         | `npm run format`                     |

## 構成

| パス                        | 内容                                                                     |
| --------------------------- | ------------------------------------------------------------------------ |
| `product/src/main.ts`       | 入口。`run()` の結果を標準出力・標準エラー・終了コードに書き出すだけ     |
| `product/src/cli.ts`        | 引数を受け取り、`{ code, stdout, stderr }` を返す。副作用を持たせない    |
| `product/tests/unit/`       | 単体テスト                                                               |
| `product/tests/acceptance/` | 受け入れテスト。CLI を子プロセスとして起動し、出力と終了コードを確かめる |

## 設計ルール

- 出力は決定的にする。現在時刻や乱数に依存する出力は、引数か環境変数で固定できるようにする
- エラーは標準エラーに出し、終了コードを 1 以上にする
- import には `.ts` の拡張子を付ける
- enum や namespace など、型除去で消せない構文は使わない
- コメントには自明なことを書かず、なぜそうしたかという判断を残す

## 禁止事項

- 工場の builder 工程で `product/tests/` を変更すること（受け入れテストは test-writer だけが書く）
- 実行時の依存パッケージを追加すること
- 絶対パス、メールアドレス、認証情報を、コードやテストに書くこと
